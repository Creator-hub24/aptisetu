# AptiSetu: Quant, Reasoning, DILR & VARC prep portal (CAT + CUET (UG) + Bank/SSC/Placements tracks)

Static site (plain HTML/CSS/JS, no build step needed to serve). Works as-is on GitHub Pages.

- **Brand / URL / contact:** `assets/js/config.js` (`BRAND`, `TAGLINE`, `SITE_URL`, `EMAIL`, `GOOGLE_FORM_URL`). `tools/build_pages.py` reads it and writes the values into every page, so after a change re-run the build. `tools/make_images.py` redraws the og:image and favicons.
- **Questions:** `data/questions.json` is generated by `/workspace/.venv-edu/bin/python tools/build_questions.py`
  (needs sympy: `python3 -m venv .venv && .venv/bin/pip install sympy`; the script stops with a clear message without it). The script checks every
  answer: 4 distinct options with exactly one correct, numeric answers recomputed, and puzzles, seating, routes and
  tournaments brute-forced. Edit the script and re-run it; don't hand-edit the JSON.
  Fields: `topic`, `difficulty`, `answer` (0-based), optional `data` (HTML table/chart), `set` (shared DILR data),
  `fixed` (keep the option order; otherwise options are shuffled at runtime).
- **CAT track:** `data/cat.json` is also written by `build_questions.py`, from `tools/cat/qa.py`, `dilr.py` and
  `varc.py` (helpers in `tools/cat/common.py`). Format: `{sections:{varc,dilr,qa:{name,questions}}, sets:{id:{kind,title,html}}}`.
  Questions have `type` `mcq` (0-based `answer`) or `tita` (`answer` string; `kind` `number` or `sequence`).
  Build checks:
  - MCQ options are distinct, with exactly one correct.
  - TITA values are recomputed.
  - Para-jumble answers are valid permutations, computed from the display order.
  - Each DILR set is brute-forced to a unique solution.
  - RC passages are 400–550 words.
  - Ids are unique, every set is used, and each set has 4–5 questions.

  In solutions, refer to options as "Option 1"…"Option 4" (bank order); `assets/js/exam.js` rewrites them to the
  shuffled letters at runtime.
- **Exam engine:** `assets/js/exam.js` is shared by CAT and CUET. A page sets `window.EXAM = "cat"` or `"cuet"` before loading it;
  the per-exam JSON, marking, timing and sectional picks are in the `EXAMS` config. Pages: `cat-practice.html`, `cuet-practice.html`. URL params `mode=sectional|practice`, `section`,
  `topic`).
  - Sectional mode: 40 min, auto-submits when time runs out; +3, −1 for a wrong MCQ, 0 for a wrong TITA.
    Picks VARC 24, DILR 22 (whole sets), QA 22.
  - Practice mode: no countdown, and the solution is shown after each answer.
- **CUET (UG) track:** `data/cuet.json` (same format; sections `gat`, `english`, `maths`; every item is an MCQ with a `part`).
  Content is in `tools/cuet/gat.py`, `english.py` and `maths.py` (helpers in `tools/cuet/ucommon.py`).
  Build checks:
  - Syllogisms and puzzles are brute-forced, and dates are checked with datetime.
  - Maths answers are recomputed with sympy.
  - RC passages are 200–300 words.
  - GK covers static facts only (no current affairs), each checked against an official or standard reference.
  - Easy/Medium general-bank items get a `cuet_part` tag and are reused in the GAT with `source: "general"`, `orig_id` and the id `G-<id>`.
    Permutations & Combinations and Probability are not reused (they aren't in the GAT syllabus).
    The site counts these shared items only once in its totals.

  Sectional mode: +5 / −1 / 0, 72 s per question (50 questions = 60 min). GAT picks QR 15, LR 15, GMA 10, GK 10.
  English and Maths have fewer than 50 questions, so their timer is pro-rated. Section B2 (Applied Maths) isn't written yet.
- **VARC rules sheet:** `FORMULAS["varc"]` in `tools/formulas.py`.
- **Pages:** `python3 tools/build_pages.py` regenerates the HTML pages. It refuses to build if any listed topic
  has fewer than 4 questions. Counts on the site (hero stats, topic badges) are read live from questions.json, cat.json and cuet.json (`assets/js/stats.js`).
- **Run locally:** `python3 -m http.server 8765` → http://localhost:8765 (the quiz fetches JSON, so file:// won't work).
- `mock-tests.html` and `placements.html` are placeholders (noindex, not linked from the nav or footer).
  Info pages (`about`, `faq`, `privacy`, `terms`, `contact`, `404`), `sitemap.xml` and `robots.txt` are generated by `tools/pages_info.py`.
- **Analytics (optional):** set `GOATCOUNTER` in `assets/js/config.js` to your GoatCounter code and rebuild; empty means no script.
  Events (via `window.track`, a no-op without GoatCounter), pattern `<mode>-<event>-<exam>-<section>`:
  `quiz-{start,finish,autosubmit}-general-{quant,reasoning,dilr,mixed}`,
  `{sectional,practice}-{start,finish}-cat-{varc,dilr,qa}`, `sectional-autosubmit-cat-{varc,dilr,qa}`,
  `{sectional,practice}-{start,finish}-cuet-{gat,english,maths}`, `sectional-autosubmit-cuet-{gat,english,maths}`.
  `utm_*` parameters in the URL are carried over to same-site links (`assets/js/layout.js`).

  **UTM scheme for links from social posts to this site** (so GoatCounter can attribute the visit). Do not add these to the site's outbound footer icons.
  `https://aptisetu.com/<path>?utm_source=<platform>&utm_medium=<format>&utm_campaign=<campaign>&utm_content=<optional>`
  - `utm_source`: `instagram`, `youtube`, `telegram`, `whatsapp`, `facebook`
  - `utm_medium`: `social` (default), `bio`, `story`, `reel`, `video`, `channel-post`, or `share` (already used on the score-share button)
  - `utm_campaign`: e.g. `daily-q`, `open-mock-15nov`, `growth-30d`, `topic-<slug>`
  - `utm_content` (optional): question id (`cq1`) or a hook variant (`hook-a`)
  Examples: bio `https://aptisetu.com/?utm_source=instagram&utm_medium=bio&utm_campaign=growth-30d`; a Reel to a question page `https://aptisetu.com/q/cat/cq1-percentages-profit.html?utm_source=instagram&utm_medium=reel&utm_campaign=daily-q&utm_content=cq1`.
  In the GoatCounter dashboard, filter or group `utm_*` query parameters so campaign variants do not fragment the main page totals.


## CAT practice sets, login and CSP (branch `cat-sets`)
- **Sets:** `tools/assign_levels.py` (run by `build_questions.py`, deterministic) gives every CAT question a `level` and, if it is in a ready set, a `practiceSet` (numbered Easy, then Medium, then Hard; slots per level set per section in `SLOTS`, e.g. Quant Easy 1–5, Medium 6–13, Hard 14–18, VARC/DILR 1–5/6–10/11–15; 10 questions each (not shown on the site); passages/data sets never split, majority level with ties to the harder; a DILR set = 2 data sets of 5). It writes `data/cat/sets.json`. Pages: `cat-quant-sets.html`, `cat-varc-sets.html`, `cat-dilr-sets.html`, `set.html?sec=qa|varc|dilr&set=N` (reuses `exam.js`).
- **Unlock rule** (`assets/js/sets.js`): Easy is open (guests: Easy set 1 only). A level unlocks once every ready set of the previous level is completed; a previous level with 0 ready sets counts as complete. Completion comes only from Supabase `set_progress` rows. This is a UI gate only: the question JSON is public.
- **Login:** `assets/js/auth.js` (Supabase email magic link, supabase-js 2.118.0 vendored in `assets/js/vendor/`). Fill `SUPABASE_URL` and `SUPABASE_ANON_KEY` in `config.js`, run the SQL files in `supabase/migrations/` in order, then rebuild (the CSP picks up the Supabase domain). Test-only mock: `?mock=1` (not linked; `?mock=0` to leave).
- **CSP:** `build_pages.py` writes a CSP meta tag on every page and moves any inline `<script>` into `assets/js/page/` (the build fails on inline scripts or `on*=` handlers).

## CUET / Bank / SSC practice sets (branch `exam-sets-phase1`)
- **Build:** `tools/exam_sets.py` (run by `build_pages.py`, deterministic) writes `data/sets/cuet.json`, `bank.json` and `ssc.json` from questions already in `data/cuet/*.json` and `data/general/*.json`; it never edits the question files. Level = the question's difficulty tag (passages/data sets whole, majority level, ties go harder). A set is "ready" only at its exact size; levels without enough questions show *Coming soon* (at least 3 slots per level).
- **Each question is in at most one set across all exams** (the build asserts it): CUET General Aptitude sets use only CUET-written items (not the Bank/SSC items reused in the GAT); the general bank is split between Bank and SSC by topic (Bank-only, SSC-only, shared topics shared out per level to fill the most sets).
- **Patterns (official sources in `SOURCES`):** CUET 25 questions / 30 min (half a paper at NTA's 72 s pace), +5 / −1; Bank Quant and Reasoning 35 / 20 min (IBPS prelims sectional), DI 2 data sets / 6 min (same pace), +1 / −0.25; SSC Maths and Reasoning 25 / 15 min (CGL 2026 sectional timer), +2 / −0.50.
- **Pages:** hubs `cuet-{gat,english,maths}-sets.html`, `bank-{quant,reasoning,di}-sets.html`, `ssc-{maths,reasoning}-sets.html`; sets open in `set.html?exam=cuet|bank|ssc&sec=&set=N` (no `exam` = CAT, unchanged). `assets/js/sets.js` handles all four exams; random quizzes and sectionals are unchanged.
- **Progress:** `set_progress.section` is `qa`/`varc`/`dilr` for CAT (unchanged) and `<exam>-<section>` for the others (e.g. `cuet-gat`, `bank-quant`), so rows never collide. **Run `supabase/migrations/20261112000008_exam_set_progress.sql` once** (section list, numeric score for −0.25 / −0.50 marking); until then CUET/Bank/SSC results are not saved.
- **Tests:** `tests/examsets.js` (data rules, hubs, guest access, unlocking, timers, marking, saved keys, 390 px light/dark screenshots in `screenshots/phase1/`), `tests/supabase/set_progress_exams.test.mjs` (pglite).
- **No question counts in the UI** (site owner's rule): set counts, timings and marking may be shown.

## Quant Lab (branch `quant-lab`)

Visual CAT Quant practice: `quant-lab.html` (hub), `quant-lab-explainers.html`, `quant-lab-generator.html`, `quant-lab-concept-lab.html`, `quant-lab-practice.html`. The pages are built by `tools/build_pages.py`. The scripts live in `assets/js/quant-lab/` and the styles in `assets/css/quant-lab.css`, using site tokens only, so light and dark follow `prefers-color-scheme`. There are 23 topics and 207 question types. The pages say "Questions generated by software and checked by our team." The lab adds no cookies, ads or analytics. Practice stats are stored only in `localStorage` (`aptisetu.quantlab.v1`).

Tests (dev-only; Playwright and axe-core are not shipped):
- `RUNS=1000 node tests/quant-lab/generator.test.js`: every type is checked against an independent solver.
- `RUNS=1000 node tests/quant-lab/viz.test.js`: every visual is checked for valid SVG.
- `NODE_PATH=<playwright+axe-core> BASE=http://127.0.0.1:PORT/ node tests/quant-lab/e2e.js`: covers 390/1280 × light/dark, every type and explainer, the labs and practice, hostile URL parameters, console errors, CSP violations, axe colour-contrast and reduced motion.

## Month 1 growth features
- **Question pages:** `tools/qpages.py` (run by `build_pages.py`) writes `q/<track>/<id>-<topic>.html` for every open-bank question (CAT, CUET, Bank/SSC), topic hubs `q/<track>/<section>-<topic>.html` and `q/index.html`; all go into `sitemap.xml`. Excluded on purpose: CAT mock and fixed sectional packs (kept unseen) and CUET items reused from the general bank (one page each, in Bank/SSC). Pages use `<base href="/">` so shared relative links work; JSON-LD `Quiz` per page.
- **Daily 10:** `cat-practice.html?daily=1`, `cuet-practice.html?daily=1` (exam.js) and `practice.html?daily=1` (quiz.js): 10 standalone open-bank questions, same for everyone on a date (date-seeded shuffle). Linked from the home page.
- **Post-test report** (exam.js): weak topics with practice links, time per question, and a progress graph from `localStorage["aptisetu.history"]` after 2+ attempts of the same test type.
- **Tests:** `tests/features.js` (same setup as `tests/flow.js`).

## Backend (Supabase + Razorpay) — Month 3
- Migrations: `supabase/migrations/` (accounts, history, passes, Open Mock with server-side scoring, `pass_gating` flag default **false**).
- Edge Functions: `create-order`, `verify-payment` (HMAC `order_id|payment_id`), `razorpay-webhook` (raw-body signature). Live keys refused unless `ALLOW_LIVE_PAYMENTS=true`; price from `PASS_PRICE_PAISE`.
- Deploy: export `SUPABASE_ACCESS_TOKEN SUPABASE_PROJECT_REF SUPABASE_DB_PASSWORD RAZORPAY_KEY_ID RAZORPAY_KEY_SECRET RAZORPAY_WEBHOOK_SECRET PASS_PRICE_PAISE`, then `bash tools/deploy_supabase.sh` and `python3 tools/set_supabase_config.py`. Secrets are never printed or committed.
- Payment UI stays hidden until `PAYMENTS_ENABLED:"on"` in config.js **and** `pass_gating=true` in `app_settings`.
- Tests: `node tests/supabase/sql.test.mjs` (needs `@electric-sql/pglite`), `deno test supabase/functions/_shared/razorpay_test.ts`, `node tests/month3.js`.
